# M-PYRE Android Standalone – public v18 source

This is the public, source-only v18 snapshot of the Android WebView shell for [History Of Sky's M-PYRE](https://github.com/HistoryOfSky/m-pyre) full firmware emulator.
Designed for POCO X6 Pro / Android 16; minSdk 26. No hardware FM-1 required.

The original private development repository and its commit history are not part of this public repository. This public project has independent commit history. See [PUBLIC_MIRROR.md](PUBLIC_MIRROR.md) for provenance and release requirements.

## Build the APK

Every push to `main` starts **Actions → Build M-PYRE Home Drum Touch v18**. You can also use **Run workflow**.
After a successful run, download the `M-PYRE-Android-v1.0.3-8Tracks-v18-HomeDrumTouch-debug-APK` artifact and unpack `app-debug.apk`. Distribute the matching `M-PYRE-v18-corresponding-source` artifact alongside any APK or standalone editor.
Copy it to your Android phone and install (allow installation from your file manager if Android prompts).
Start the app, tap POWER, and use the virtual keyboard, knobs and buttons.

## Low-latency test build (Android)

- The published M-PYRE emulator used `latencyHint: "playback"`. This Android variant requests `"interactive"` for responsive live playing.
- The audio context uses the default output sample rate of the device (often 48 kHz on Android). The original DSP still generates at 44.1 kHz, and its worklet converts to the output rate.
- The app displays WebAudio `baseLatency` and `outputLatency` (when available). **These are not measurements of total touch-to-sound latency**.
- The firmware processes virtual key input in 16-ms UI frames; this build retains the timing to avoid changing sequencer semantics.
- The app has a **different application ID** (`dev.mpyre.standalone.lowlatency`) from the first prototype, so you can install both side-by-side without overwriting songs. Export an `.mpyre` song from the first app and import it in this one if needed.
- Bluetooth headphones can have significant extra delay. Test with the smartphone speaker or wired headphones before comparing.
- Debug APK signatures generated by CI are not stable between builds; later builds may need reinstall or a permanent release signing key.

## Audio integrity

- The real upstream firmware DSP / sequencer / UI is built as WebAssembly by `tools/build_emu.py` at M-PYRE **v1.0.3**, pinned commit `f50926b251c49a67df882cc8d33d1044005cf9d8`.
- The guitar, palm mute and bass soundpack is downloaded directly from the official v1.0.3 release, size- and SHA-256-verified, then embedded unchanged into the offline HTML.
- **Not fully identical to the official device sound:** the source recordings for the official HEAVY KIT drums and the original cabinet IRs are absent from the public upstream repository. The build uses CC0 drum WAVs and the upstream generic cabinet fallback.
- WebAudio runs inside Android WebView. Actual playback/latency must be tested on the target device.
- Songs in the four slots are saved in localStorage. You can import and export `.mpyre` projects via Android's document picker.
- No Internet or USB permission is needed by the installed APK. The build runner requires Internet to fetch upstream sources and the sample pack.

## Rebuild yourself

Tools: Python 3.12, LLVM clang with wasm32 backend + wasm-ld, Git, Android SDK 35, Gradle 8.9, JDK 17.

```bash
python -m pip install -r requirements.txt
python scripts/prepare_emulator.py
gradle :app:assembleDebug
```

APK path: `app/build/outputs/apk/debug/app-debug.apk`.

## V8: Offline official editor in Android

Open **POWER**, then **Options → FULL EDITOR**. This bundles the actual GPL-3.0-licensed
M-PYRE v1.0.3 standalone web editor, with twelve pages: Live, Sound (AMP, pedal,
effects, FM6), Sequencer (piano roll, locks, nudges, ratchets), Tracks, Song,
Library, Samples, Kits, Drum Synth, Projects, Settings and Theme.

The full editor runs entirely offline in a same-origin WebView frame. The editor
connects via a local Web MIDI/SysEx adapter to the real, already running M-PYRE
AudioWorklet WASM instance (no physical FM-1, external browser, or fake mock
instrument). Touch adaptations provide a horizontal scrollable tab bar, enlarged
sliders, buttons and piano keys, and Android Back closes the editor. The previous
quick touch Song Studio stays available as a separate Options entry.

**Hardware differences/limitations:** The underlying upstream browser emulator
does not implement the original FM-1's persistent NOR flash or USB peripheral.
We provide RAM-backed user preset banks and sample slots. These are now backed
by the Android app's localStorage: the original guitar soundpack remains the
default, and edited user samples, user presets and synthesized drums are saved
after valid editor commits and restored on restart. Android uninstallation
still removes app-local data; export important projects. Hardware firmware flashing
and some original
device-backup/theme/arrangement-store operations may be unavailable. The original
HEAVY KIT drum samples and cabinet IRs are not present in upstream public assets;
the original guitar/bass pack remains exact and the fallback drum assets CC0.

An Android Storage Access dialog handles full-editor file exports, including MIDI
and preset files. Existing v7 APK stays installed alongside this APK; the new
package ID avoids debug key update failures and preserves earlier local songs.

- Quick Chain A–D now switches between actual saved patterns on bar
  boundaries, looping in order; the original **SAVE + two or more keys**

- **Song Mode** follows configured sections and bar counts, and restores

- Song arrangement (36-byte configuration) and SONG/LOOP selection are now
  saved alongside the browser's existing project slots in localStorage,
  without changing the `.mpyre` project format.
- The Android Song Studio has a simple, touch-friendly **PATTERN CHAIN**
  panel: add A/B/C/D (up to eight, repeats supported), CHAIN LOOP and
  CHAIN AUS. An active chain can start transport automatically.
- The full original editor's Live/SONG pages use the same fixed firmware
  functionality; there is no second mock audio or MIDI sequencer.
- Tests advance the REAL WebAssembly audio render clock through A→B→A
  quick chaining and A→B complete-song playback/restore.
- This APK uses a separate package ID to preserve installations of
  the previous build. Existing `.mpyre` projects can be imported into v9.

## v10: Android USB-MIDI peripheral ↔ original desktop M-PYRE editor

**Prerequisite:** The phone/HyperOS build must offer **USB preference > MIDI**.
The phone's USB gadget MIDI port is a system feature, not a spoofed FM-1 USB
descriptor; the APK cannot force-enable it or change its hardware VID/PID/name
without privileged device modifications.

- Native Android `MidiManager` discovers a bidirectional `TYPE_USB` device,
  opens its MIDI input/output ports, watches USB attach/detach, and exposes
  the connection status under **Options → USB ↔ PC WEBEDITOR**.
- Fragmented USB SysEx is reassembled and validated to a maximum of 640 bytes.
  Messages are dispatched to the **same running M-PYRE audio/WASM firmware** as
  the internal editor; replies are sent back over USB MIDI in real time.
- Includes the **complete original desktop M-PYRE editor**, minimally modified
  to admit system port names such as `Android USB Peripheral` and `USB MIDI`.
  The editor still checks the firmware's actual INFO response before connecting.
  Download the PC companion HTML from the separate GitHub Actions artifact
  `M-PYRE-Original-PC-Editor-Android-USB`; open in Chrome/Edge on a computer.
  If local file Web MIDI permissions are restricted, serve it over
  `http://localhost` (e.g. `python -m http.server 8765`).
- The *unmodified upstream hosted editor* only sees phone ports whose system
  names match its hard-coded regex; it cannot reliably identify typical Android
  peripheral names. Use the included original-editor companion instead.
- Automatic CI test verifies real firmware INFO and BPM SET through a
  fragmented simulated USB stream; actual phone USB-gadget support must be
  verified on-device.
- Keep the Android app foregrounded and press POWER. Do not use its embedded
  Full Editor simultaneously with the external PC editor.
- New package ID keeps v9 and its local songs installed. Import existing
  `.mpyre` song projects into v10. Not a substitute for a powered FM-1 device.

## Windows Web MIDI port discovery diagnostics

The original PC editor only recognized names like `USB-MIDI` and required the
MIDI input and output port names to match. On Windows, a POCO/Android gadget may
appear as `USB MIDI Device` (space, not hyphen) and can expose differently named
`MIDIIN...` and `MIDIOUT...` ports. The current companion editor discovers
these safely and still requires the real M-PYRE firmware's INFO reply before
connecting. Its new **USB / MIDI diagnostics** panel lists the raw Web MIDI
input and output ports and distinguishes no MIDI devices from no SysEx answer.

The Android v11 APK is unchanged by this PC-only compatibility fix. Windows
must enumerate Android's MIDI gadget, Chrome or Edge needs SysEx permission,
and the M-PYRE app on the phone needs POWER on. A local Android USB port
alone does not confirm a Windows browser MIDI port is present.

## v12: Fix official PC Editor Song "Error: short reply"

The browser firmware (FELUCCA_FLASH=0) previously replied with just rc=4
for each backup SysEx command, even though INFO reported protocol v12.
The PC Song page expects BK_LIST's two-byte header plus each object's
ID/length/CRC. It crashed with "short reply".

This build implements the full BK_LIST/BK_GET/BK_PUT envelopes in the
same live WASM firmware over the existing USB-MIDI bridge, for the
working project, the original 36-byte Song arrangement (within an
84-byte PER3-compatible settings image) and four project sections A-D.
Requests are checked, snapshotted, packed via the original pack7,
validated using real firmware CRC32, and committed to in-memory
sections and native song arrangement; they persist through the
existing browser localStorage autosave.

WARNING: Other physical FM-1 flash backup objects such as FM6 patch
bank and user-sample bulk transfers are deliberately *not advertised*
by the new host BK_LIST; their existing dedicated editor functions
and Android storage bridges remain separate.

The new Android package ID preserves the previous v11 installation
and its local songs. Export/import .mpyre projects where appropriate.
The existing PC editor v12 (USB port diagnostics) is unchanged.

## v14: Expressive sequencer — drag notes + chromatic Note Grid + bulk editing

The **original PC editor and Android's embedded Full Editor** now offer three
switchable views: **Grid**, **Piano roll**, and **Note grid**.

**Note Grid** is a pitch-vs-time matrix with 25 chromatic note rows, contrasting
black keys and marked C/octave boundaries, note starts, sustained TIE segments,
and x2–x4 ratchet labels. Page horizontally in 16-step chunks and move the
pitch viewport by octaves. Tap a cell in Navigate mode to place or remove a
pitch; track chords are still limited to the firmware's four notes per step.

**Drag tools** on the flat grid, Note Grid and drum lanes:
- **Tie**: one NOTE followed by firmware TIE steps, sustaining through the
  selected range; same-cell tap in Note Grid toggles an individual pitch.
- **Repeat**: independent NOTE triggers over a dragged step range, spacing
  every 1/2/4 steps, optional x1–x4 ratchets for rapid notes.
- **Erase**: REST steps for synths, or only the selected drum lane for drums.
- **Select**: select contiguous steps for bulk editing.

**Bulk edit**: select all or a range, copy/paste, clear, shift left/right,
transpose ±1/±12 semitones, velocity ±10, accents on/off and apply x1–x4
ratchets. Drum tracks support painting/erasing lanes, copy/paste/clear,
and per-lane ratchets. Edits are written over the existing **real
STEP_SET / DRUM_STEP SysEx firmware protocol**; they are not just drawn
in the browser. Large bulk operations take multiple MIDI roundtrips.

The v13 Song tab's **PLAY SONG / STOP** buttons remain available in the PC
editor. The new v14 Android package ID installs separately from v12 and v11
to protect saved song data. The PC-only HTML artifact is
`M-PYRE-PC-WebEditor-NoteGrid-v14`.


## v15: Direct LCD touch mode, larger FM-1 display, Classic switch

The **◯ CLASSIC / ◉ LCD TOUCH** button next to Optionen changes the live emulator
input mode. **CLASSIC is the default**; the last choice is remembered per
installation. Classic leaves the prior 27-key keyboard, seven encoder touch
controls, audio engine, Full Editor, Song Studio, USB MIDI and saved projects
unchanged. The new package ID `dev.mpyre.standalone.lcdtouch` installs beside
v14 so you can test without replacing songs stored by older versions.

**LCD TOUCH** enlarges the 240×240 original firmware display to up to
72% of the landscape viewport height (previously 44–46%); portrait uses a
centred, enlarged square with the remaining controls below it. The rendering
still comes from the exact same firmware framebuffer, with nearest-neighbour
pixels. Touches are transformed to 240×240 coordinates; no screen recognition
or duplicate instrument is involved. The on-screen FM-1 controls and keyboard
remain accessible, although the touch layout makes the keyboard shorter.

Supported directly on the original M-PYRE LCD:

- **Status/header:** tap the play icon to play/stop; drag the BPM area to
  change tempo; tap the upper-right page title or swipe it to change pages;
  tap the upper-left corner to return to tracks; long-press the header for
  the firmware's actual system menu.
- **TRACKS:** tap one of four rows to select a track, tap its right-hand
  status area to mute/unmute, or slide there to adjust level. Long-press a
  track to open its native sequencer (or DRUMS).
- **DRUMS:** tap a cell to toggle a real drum hit, drag across cells to
  paint more, tap a row's label to pick the sound; tap Grid / Kit / Edit at
  top right to switch views. In Kit and Edit, tap a pad to select and audition
  its sound. The original undo and arrangement-playback protections are used
  for grid changes.
- **SOUND, EFFECTS, AMP, parameter pages:** drag large value cards or the
  four drawn bottom controls to turn the same firmware encoders; tap the
  left/right half for minus/plus one step. FX send faders can be tapped at
  a particular height or dragged; tapping the scale diagram selects its key.
- **SEQ:** tap a visible piano-roll time position or a 64-step overview
  position to move the actual firmware cursor. Existing knob controls edit
  the selected note, length, accent and other parameters.
- **SONG:** tap a row to select a chain entry; change its section/bars/length
  through the four drawn bottom dials; tap the mode/transport header.
- **Firmware MENU:** tap a section tab, tap a setting to cycle it, or drag a
  setting to adjust it; tap MENU to exit. Hardware calibration and bulk MIDI
  learn clearing remain Classic-only to avoid accidental destructive actions.
- **Function layers:** the 4×4 displayed STEP, SCALE, MIX and SONG tiles are
  tappable while their respective layer is active. FX punch-in, erase and
  roll layers continue to use the existing keyboard because their effects
  depend on press duration / live note state.

**Notes:** This is an Android emulator feature, not a hardware FM-1
touchscreen modification. The actual phone's touchscreen is required to
evaluate ergonomics and audio latency. Use the Classic button whenever a
specific page's touch gesture is less convenient than a real FM-1 control.
The built-in Full Editor and Song Studio are still available for precise
sequencer editing, especially tiny cells or bulk operations.

Build/test is the existing GitHub Actions workflow, plus
`python tests/check_lcd_touch.py` and
`node tests/test_lcd_touch.cjs` after `scripts/prepare_emulator.py`.

## v17: USB-C to USB-B class-compliant MIDI devices (Android USB host)

The **Options → USB-MIDI VERBINDUNG** selector offers two explicit modes:

- **PC-WebEditor** (default): Android acts as the PC-facing USB-MIDI *peripheral*; Android's system USB mode **MIDI** is required, as in v16.
- **USB-B MIDI-Gerät**: Android acts as the USB *host*. Connect the phone's USB-C plug to a **class-compliant USB-MIDI 1.0 device** with a USB-B socket. Android's `MidiManager` recognizes the attached `UsbDevice` and opens available MIDI input/output ports. Controllers that only send notes are supported as well as bidirectional MIDI instruments. Incoming notes and M-PYRE SysEx reach the **existing live emulator**. This does **not** make the bundled Full Editor control an arbitrary external synthesizer.

If Android sees an attached USB device but not a MIDI port, the app explains that the device may not expose USB-MIDI 1.0. The USB-C to USB-B **cable has no chip or driver**; a USB printer or audio-only interface is not automatically a MIDI device. For host mode, do **not** select Android's "USB use → MIDI" gadget setting. A powered hub may be required for devices drawing too much power.

This update does not implement raw USB-MIDI packet transfers, device flashing, vendor-specific USB protocols or external editor passthrough. Only Android's built-in MIDI 1.0 byte-stream transport is supported. USB MIDI 2.0/UMP-only interfaces are not supported by this mode. Hardware must be tested on-device; passing CI is not proof of compatibility with a particular instrument.

v17 uses a **distinct Android application ID** to preserve previous v16 songs and APKs. Import/export projects as needed. APK build artifact: `M-PYRE-Android-v1.0.3-8Tracks-v17-USBHost-debug-APK`.
